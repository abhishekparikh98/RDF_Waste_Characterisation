When I started this coursework, I was both excited and nervous because it was one of the first times I was writing a complete Python program that calculates students’ marks and classifies them into categories. The idea that I could build something that mimics a real university grading system was quite motivating. I began the process by planning what the program should do and then designed a flowchart to visualize each step clearly before writing any code.

How I decomposed the problem
I broke the main task into smaller, logical parts so that I wouldn’t get overwhelmed. First, the program needed to collect inputs: the student’s name and marks for coursework 1, coursework 2, coursework 3, and the final exam. Next, I calculated the overall score using weighted percentages: 10% from coursework 1, 20% from coursework 2, 30% from coursework 3, and 40% from the final exam. I then used the round() function to make the score a whole number for consistency. After that, the program checked which range the overall score fell into and assigned the correct category, such as “Upper First,” “First,” “2:1,” or “Third.” Structuring the problem this way made it easier to test and debug each part separately.

Usefulness of the flowchart
The flowchart turned out to be extremely helpful. It gave me a clear visual of how data would flow through the program—from input to processing to output. Whenever I got stuck or made an error, I could look back at the flowchart to trace my logic. It also helped me explain my approach to others because it made the process easy to follow. I realized that drawing a flowchart before coding saves a lot of time later because it forces you to think logically about every step.

Challenges and bugs encountered
One of the biggest challenges was ensuring that the score ranges were accurate and that boundary values were included. Initially, I used comparison operators like > and <, which caused errors for students who scored exactly at the range limits. I fixed this by using >= and <= instead. I also had a small bug where I forgot to round the overall score, which led to decimal values like 70.3 instead of 70. Another issue was a typing mistake—writing courswork3 instead of Coursework3—which resulted in a NameError. These small mistakes taught me the importance of careful testing and debugging.

What I learned
I learned that programming isn’t just about writing code—it’s about logical thinking and planning. I became more comfortable with functions like input(), int(), and round(). I also understood how weighted averages work in practice and how conditional statements (if, elif, else) help in decision-making.

Improvements and future goals
If I had more time, I would improve the program by allowing multiple students to be entered at once, saving the results to a text or CSV file, and adding colour-coded outputs to make it visually appealing. I would also include a summary at the end showing how many students achieved each category and create a menu-driven interface for easier use.

Final thoughts
Overall, this project made me feel proud and confident. It helped me realize that even a simple program can perform useful, real-world tasks. I started with an idea and ended with a functional grading system that works perfectly. It was a rewarding learning experience that strengthened both my Python skills and my logical thinking.
